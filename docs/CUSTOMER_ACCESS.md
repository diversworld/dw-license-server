# Customer authorization

Users have explicit Customer assignments and a separate globalAccess flag. Upgrade defaults existing users to global access, preserving their existing role permissions. In User administration, disable global access and assign the permitted customers for restricted support/sales/auditor accounts. Roles grant operations; assignments constrain the objects. Empty assignments grant no customer records. Changing assignments/global access revokes old sessions. Restricted administrators cannot manage users or the shared product catalogue. Product choices remain shared read-only catalogue data.

The request-scoped Doctrine filter constrains customer/license/activation/action/API-credential queries, counts and association choices. Guards on resolved arguments, EasyAdmin CRUD objects, voters, persistence and license issuance also protect direct IDs and already-loaded entities. Scope comes from authenticated User assignments, never from the installation tenant string. The existing activation/refresh protocol retains license-key/signed-token authentication for anonymous installations. Authenticated restricted users cannot use that protocol against a foreign customer's license even if they know its key. Management API credentials receive explicit customer scopes separately.

New immutable audit contexts include customerId under the existing canonical hash. Scoped audit views expose only matching contexts. Historical entries without reliable recorded ownership remain visible to global accounts; they are neither guessed nor rewritten. The global chain verifier runs through an operator CLI without a request filter. Background jobs run with explicit service-level customer checks where acting for an external principal; raw SQL and native queries do not inherit Doctrine filters. No scoped raw-SQL export endpoint is provided.

Apply migration Version20261003101128 during a controlled upgrade. It creates user_customer and global_access with guards for partially applied MySQL/MariaDB DDL. Downgrade is blocked while restricted accounts or assignments exist. CLI-created users retain the backwards-compatible global default; an administrator must deliberately restrict customer accounts before giving access. Customer portal roles and routes are separated from administration.
